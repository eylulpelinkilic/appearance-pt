# Experiment 2: how much of Sonata's concatenation gain can a point-only student recover?

The pilot ([Experiment 1](../Experiment1_Concatenation/README.md), `docs/pilot_concat.md`) found that concatenating
lifted DINOv2 features to frozen Sonata raises linear-probe mIoU on ScanNet++ v2 val from 30.83 to 40.73. That needs
30 posed photos per scene at test time. Here the images are used only during training:

1. **Per-view observations** of training points. This is the pilot's lifting, stopped just before it averages over
   cameras (`lifting.observe`).
2. **Cross-attention teacher.**
   - Query: the point's frozen original Sonata feature.
   - Keys: two input views' DINOv2 features. Values: those DINOv2 vectors, unchanged.
   - Trained to predict a third, held-out view's DINOv2 feature (cosine loss).
   - Only W_q and W_k are trained.
3. **Point-only student.** Continued training of Sonata from the same `sonata.pth`, on xyz, colour and normal only.
   Through a small head, it learns to match the frozen teacher's detached weighted DINOv2 vector:
   `L = mean_p [1 − cos(h(f(p)), stop_gradient(t(p)))]`.
4. **Evaluation on the pilot's terms.**
   - Teacher and head are discarded; the student is frozen.
   - The pilot's feature layer, the pilot's labelled sample and probe recipe, all 50 val scenes and every vertex,
     scored with the official evaluator.
   - Compared with the pilot's frozen Sonata and Sonata + DINOv2 rows. Those are reused from the pilot's saved
     per-scene confusion matrices, not rerun.
5. **The PDF report**, built from the saved metrics.

Start commit (the pilot's last): `6dcd7bdd4f337f550fc31b33382d2f1a442fdc6d`. All settings are in `config.json`.

## Running on Kaggle

**Notebook:** `experiments/Experiment2_CrossAttention/notebooks/exp2_cross_attention.ipynb`. It runs steps 1–5 in
order. The `RUN` cell chooses the mode.

**Settings:** GPU T4 x2, Internet on, secret `GITHUB_TOKEN`, environment pinned to the wheelhouse image.

**Inputs:**

| Input | Why |
|---|---|
| `appearance-pt-wheels` | the offline environment |
| `scannetpp-core-train-a`, `scannetpp-core-train-b` | the 200 train scenes: point clouds, DSLR views, labels |
| `scannetpp-core-val` | the 50 val scenes: point clouds, labels, raw mesh and annotations for the official ground truth |
| `pilot_04_eval` notebook output | `pilot_concat/step5/confmats.npz` and `results.json`: the two baseline rows |
| *(only to resume)* the earlier `exp2_cross_attention` output | saved observations, teacher and student checkpoint |

**Run order:**

1. **`RUN = "smoke"`**, about 30–45 min. Uses 6 train scenes (2 of them dev) and 2 val scenes, and runs every step.
   - It runs the pre-run checks listed below.
   - It measures peak T4 memory, storage and time per scene and per step.
   - It sweeps the student's trainable layers × crop size and prints a recommendation.
   - It writes a **Preliminary** report.
   - Paste the SUMMARY blocks back.
2. **Record the student choice.** `trainable`, `crop_points`, `steps` and `recorded_from_smoke` go into
   `config.json` → `student_choice`, then commit and push. The full run refuses to train the student until this is done.
3. **`RUN = "full"`**, about 3–4 h; the smoke run prints its own estimates. **This is a run longer than 2 h, so it needs
   the user's go-ahead.** It covers 200 train scenes (20 dev), the recorded student budget, 200 + 50 scenes for
   evaluation, and the final report.

**Outputs** go to `/kaggle/working/Experiment2_CrossAttention/`:

| Path | Contents | Size (full run, estimated) |
|---|---|---|
| `observations/` | per-scene observation store, `summary.json` | ≈ 6 GB |
| `teacher/` | `teacher.pt`, `checks.json`, `diagnostic.json` | < 10 MB |
| `student/` | `student.pth`, `checkpoint.pt` (with optimizer), `train_log.json`, `checks.json`, `smoke.json` | ≈ 2 GB |
| `evaluation/` | `results.json`, `confmats.npz`, `probes.pt` | < 50 MB |
| `reports/` | **`sonata_cross_attention_report.pdf`**, `metrics.json` (everything the PDF reads), `figures/` | < 5 MB |

Temporary disk, not kept: `/tmp/exp2_points` (point arrays of the train scenes, about 8 GB) and
`/tmp/exp2_probe_features` (about 5 GB).

**Between sessions and resuming.** Save the version, so the output is kept, and attach it to the next session.
- Step 1 skips scenes whose observations are already saved.
- Step 2 reuses `teacher.pt`.
- Step 3 continues from `checkpoint.pt`, which is written every 30 min and at the end, if trainable layers, crop
  size and step budget match.
- Steps 4 and 5 rerun quickly.

To rebuild only the report: `python experiments/Experiment2_CrossAttention/step5_report.py --out <output dir>`.

## Checks

**Run on CPU** (`tests/test_exp2.py`, synthetic rooms, stand-ins for Sonata, DINOv2 and the toolbox):
- the observations' mean equals `lift()` exactly, with one observation per (point, camera) and pixels that re-project;
- camera triples are distinct and the held-out camera is never an input;
- equal attention weights reproduce the mean;
- one teacher update changes W_q, a second W_k;
- one student update changes a trainable encoder stage and leaves frozen ones unchanged;
- `sample_points` equals the pilot's;
- steps 1–5 end to end, including the point-only probe pass, the image-free self-check, the comparison with saved
  pilot outputs and the PDF;
- the full mode refuses to train before the smoke choice is recorded.

**Still to run on Kaggle (the smoke run)**, on real data with real Sonata, DINOv2, spconv and the toolbox:
- the same checks;
- peak T4 memory of steps 1–4;
- seconds per step for each trainable choice and crop size;
- storage of the observation store and checkpoints;
- the runtime estimate for the full run;
- the image-free check on a real val scene.
