# Pilot: do lifted DINO image features complement point encoders, including Concerto?

A ScanNet++ v2 version of Concerto's pilot study (NeurIPS 2025, Sec. 2.1, Table 1). Frozen encoders,
one linear probe per feature set, top-100 semantic classes, scored on all 50 val scenes with the
official toolbox. Concerto's ScanNet linear-probe numbers: DINOv2 63.1, Sonata 72.5, concatenation 75.9 mIoU.
On ScanNet++ val the Concerto paper reports linear probing at 38.9 (Sonata) and 45.6 (Concerto).

**Key question (since 2026-10-26):** does lifted DINO still add information on top of Concerto (K+ vs K),
which was itself trained to predict DINOv2 features (ViT-g/14 with registers)? Report the per-class
gains of K+ over K and the split into visible and never-seen points.

| Config | Features |
|---|---|
| A | DINOv2 ViT-L/14 with registers (518 px), lifted to points |
| B | Utonia |
| C | Utonia ⊕ DINO (also with both blocks PCA-reduced to equal width) |
| S | Sonata (sanity check: Concerto reports 38.9 mIoU linear probing on ScanNet++ val) |
| S+ | Sonata ⊕ DINO |
| K | Concerto (`concerto_large_origin`; sanity check: Concerto reports 45.6 mIoU linear probing on ScanNet++ val) |

| X | raw xyz, colour, normal |

## Files

- `encoders.py`: load Utonia / Sonata / Concerto / untrained PTv3 for a T4 (pinned HF weights, no
  FlashAttention, SDPA attention), per-encoder input transform, `encode()` → upcast features + input→voxel index.
- `scenes.py`: numpy scene helpers (Pointcept-format scene dirs; tiling for the size benchmark).
- `lifting.py`: DINOv2 patch features, projection into DSLR views, point z-buffer (occlusion variants), averaging over views.
- `probes.py`: linear probes on frozen per-point features: the half-room health check, configurations, the step-3
  feature store, training in phases, folding into per-block weights.
- `stages.py`: per-stage encoder features gathered at chosen vertices; spatial tiles on out-of-memory.
- `pipeline.py`: per-scene pieces of steps 3 and 5 (models, background loading, views with DINO features).
- `metrics.py`: the official top-k multilabel confusion matrix on the GPU, mIoU, paired bootstrap over scenes.
- `official.py`: the toolbox's own GT and `eval_semantic`, in-process.
- `step3_features.py`, `step4_probes.py`, `step5_eval.py`: steps 3–5 (notebook `pilot_03_probes`).
- `step1_encoders.py`, `step1b_concerto.py`: step 1 entry points (demo-room checks, then time/memory per scene).
- `step2_lift.py`: step 2 entry point (pose-convention check, lifting on 3 val scenes, visual checks).
- `notebooks/`: Kaggle notebooks, generated by `scripts/make_notebooks.py`.

Imports: `PYTHONPATH=src:third_party/utonia:third_party/sonata:third_party/concerto` (the notebooks set it).
