# appearance-pt

Self-supervised **2D→3D representation learning** on **ScanNet++ v2**: learning better general point
cloud encoders from images, without labels, in the direction of
[Concerto](https://github.com/Pointcept/Concerto) (NeurIPS 2025). Encoders are evaluated frozen,
mainly by linear and decoder probing on ScanNet++ semantic segmentation (top-100 classes, official
toolbox). Supervised segmentation methods such as [DITR](https://github.com/RWTHVision/ditr) are
related work, not a target. (Direction changed on 2026-10-26: [decisions D14](docs/decisions.md).)

**Reference encoders:** Sonata (3D-only SSL), Concerto (joint 2D-3D SSL), Utonia. On ScanNet++ val
the Concerto paper reports linear probing at 38.9 mIoU (Sonata) and 45.6 (Concerto), and decoder
probing at 48.3 (Concerto). These models saw ScanNet++ val scenes, unlabelled, during pretraining.

**Now: the pilot** ([experiments/pilot_concat](experiments/pilot_concat/README.md)). Linear probes on
frozen Utonia, Sonata and Concerto features, alone and concatenated with DINOv2 features lifted onto the
points. The key question: does DINO still add information on top of Concerto, which was trained to
predict DINOv2 features?

**Next (planned):** continued pretraining from Sonata weights on ScanNet++ under a fixed GPU budget,
with Concerto's cross-modal objective as the control against new objectives (for example,
higher-resolution cross-modal prediction from the DSLR images and dense laser scans).

## Layout

```
configs/            our configs; scannetpp_subset.json (the 250 scenes); protocol_reduced.py (supervised draft, postponed)
  env/              kaggle-requirements.in (what the wheelhouse adds on top of the Kaggle image)
docs/               decisions.md (dated log), results.md (all runs)
experiments/        pilot_concat/: do lifted DINO features complement Utonia / Sonata / Concerto? (linear probes)
notebooks/          Kaggle notebooks, GENERATED by scripts/make_notebooks.py (do not edit by hand)
scripts/setup/      env_report, build_wheels, install_env, smoke_test (+ smoke/ checks), kaggle_bootstrap
scripts/scannetpp/  token-safe ScanNet++ download, packing and the dataset check (M2)
src/appearance_pt/  our code: env records, logging, ScanNet++ download/packing/reading, DSLR cameras, safe checkpoint reading
tests/              local CPU unit tests
third_party/        pinned git submodules: Pointcept, concerto, ditr (reference only), scannetpp, sonata, utonia
                    (never edited in place)
```

No ScanNet++ data, nothing derived from it, and no checkpoints are ever committed (ScanNet++
terms forbid redistribution). Processed data lives in private Kaggle Datasets.

## How to reproduce

### Local checkout (code only; no GPU needed)
```bash
git clone --recurse-submodules --shallow-submodules <your-private-repo-url> appearance-pt
cd appearance-pt
uv sync --group dev && uv run pytest        # CPU unit tests
uv run python scripts/make_notebooks.py     # after editing any wrapped script
```

### Kaggle (all GPU work)
One-time account setup: add Kaggle Secrets `GITHUB_TOKEN` (fine-grained, read-only *contents*
access to this repo) and `SCANNETPP_TOKEN`. Import a notebook with *File → Import Notebook*,
then set REPO/REF in its config cell. Every notebook clones the repo at REF, logs the resolved
commit, and runs one entry point with logs in `/kaggle/working/logs/`.

| Step | Notebook | Settings | Produces |
|---|---|---|---|
| 1 | `notebooks/m1_00_env_report.ipynb` | GPU T4×2, Internet on, both secrets | environment report (`m1_env_report.json`) |
| 2 | `notebooks/m1_01_build_wheels.ipynb` | GPU T4×2, Internet on, `GITHUB_TOKEN`, pinned environment; **Save & Run All** | `wheelhouse/` → create the **private** dataset `appearance-pt-wheels` from the output |
| 3 | `notebooks/m1_02_smoke_test.ipynb` | as step 2 + input dataset `appearance-pt-wheels` | `smoke/summary.json`, `smoke/sonata_semseg_topdown.png` |

Later milestones add data, training and evaluation notebooks in the same pattern; each result
row in `docs/results.md` links to its git commit, config, seed and environment record.
